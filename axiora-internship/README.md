# Axiora Labs — GenAI Internship (WordPress plugin)

Everything for the internship flow, in one plugin:

> **Student fills the form → clicks Save → the record is stored → admin signs in at a separate portal → sees every submission → tracks it → changes the status → the change is saved and shows on the dashboard.**

It is a **plugin, not theme code**, on purpose: the `axioralabs_wp` theme is generated by
`build/build_theme.js`, so anything added to the theme folder is wiped on the next rebuild.
Nothing here touches the theme — it only borrows its header, footer, icon sprite and CSS
variables so the public page looks native.

---

## 1. Install

1. **WP Admin → Plugins → Add New → Upload Plugin** → `axiora-internship.zip` → **Install** → **Activate**.
2. **Settings → Permalinks → Save Changes** (once, so the `/internship-admin/` URLs resolve).

Activation does the rest automatically:

- creates the two database tables,
- creates the **GenAI Internship** page at `/genai-internship/` and assigns it the plugin's page template
  (this is the page that was returning *Page not found*),
- creates the **Internship Admin** role,
- creates the private resume folder `wp-content/uploads/axiora-internship/` with deny rules.

If the page already exists at that slug it is reused, not duplicated.

---

## 2. The two URLs

| What | URL |
|---|---|
| Public application form | `https://axioralabs.ai/genai-internship/` |
| Admin portal (separate login) | `https://axioralabs.ai/internship-admin/` |

The form can also be dropped into any other page with the shortcode `[axiora_internship_form]`.

---

## 3. Creating an admin login

The portal has its own sign-in screen, but it authenticates against WordPress accounts —
so password hashing, sessions and password resets are all handled by WordPress rather than
by hand-rolled code.

1. **Users → Add New**
2. Set **Role → Internship Admin**
3. Give them the portal URL. That account can sign in at `/internship-admin/` and **cannot**
   reach the WordPress dashboard for anything else.

Existing administrators and editors already have access.

---

## 4. What the admin can do

**Dashboard** — total applications, last 7 days with the week-on-week change, how many are
awaiting review, how many are mid-pipeline, how many selected; a 14-day submissions chart; the
pipeline broken down by status; the latest eight applications; and the top institutions.

**All Applications** — search across name, email, phone, college, city and reference number;
filter by status, course and date range; sort any column; select several rows and move them
to a new status in one go; page through; export the current view to CSV.

**One application** — everything submitted, the resume, internal notes, and the full activity
trail of who changed what and when.

**Status** — pick a stage, optionally attach a note, optionally email the applicant the update.
Every change is written to the timeline.

### The pipeline

`New` → `In Review` → `Shortlisted` → `Interview Scheduled` → `Selected`, with `On Hold` and
`Not Selected` available at any point. To rename or add stages, filter `axiora_internship_statuses`
in a small mu-plugin — nothing else needs changing, the dashboard, filters and sidebar all read
from that one list.

---

## 5. Settings

**WP Admin → Internship** sets where new-application alerts go (one address or a comma-separated
list) and whether applicants get a confirmation email. Defaults to `sales@axioralabs.ai`.

> Email needs SMTP configured to deliver reliably from Hostinger — install **WP Mail SMTP**
> (smtp.hostinger.com:465, SSL, user `sales@axioralabs.ai`), as already noted in the main README.
> The form still saves fine without it; only the emails would fail.

---

## 6. Security notes

- Resumes are stored in `wp-content/uploads/axiora-internship/` under an unguessable filename,
  with `.htaccess` / `web.config` deny rules, and are served only through a capability- and
  nonce-checked download endpoint. They never appear in the media library.
- Uploads are checked with `wp_check_filetype_and_ext()` and capped at 5 MB; only PDF, DOC and DOCX.
- Every query is prepared; `ORDER BY` is whitelisted.
- The form carries a nonce, a honeypot, a minimum-time check, one-application-per-email-per-day,
  and a five-per-hour-per-IP rate limit.
- All portal writes are nonce-checked and capability-checked.
- Deleting the plugin removes its settings and role but **deliberately leaves the application
  data and resumes alone** — see `uninstall.php`.

---

## 7. Rebuilding the zip

```bash
node build/build_plugin_zip.js     # from the repo root → axiora-internship.zip
```

Uses the same WordPress-safe ZIP writer as the theme (`build_zip.js`); don't use Windows
"Compress to zip".

## 8. File map

| Path | What it does |
|---|---|
| `axiora-internship.php` | Bootstrap, activation, rewrite rules, role, private upload dir |

| `includes/class-settings.php` | The wp-admin settings screen |
| `includes/charts.php` | Inline SVG trend chart + pipeline bars (no chart library) |

| `assets/` | `form.css` / `form.js` for the public page, `portal.css` / `portal.js` for the portal |
