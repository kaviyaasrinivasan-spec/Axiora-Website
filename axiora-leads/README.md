# Axiora Labs — Client Dashboard (WordPress plugin)

Captures every lead from the site's contact form and gives it a searchable, filterable, branded
dashboard, entirely separate from wp-admin:

> **Client fills the "Book Your Free AI Automation Audit" form on `/contact/` → clicks Book A Call
> → the theme emails sales@ as before AND fires an action → this plugin stores the lead → an admin
> signs in at a separate portal → sees every lead → tracks it → changes the status.**

It is a **plugin, not theme code**, on purpose: the `axioralabs_wp` theme is generated by
`build/build_theme.js`, so anything added to the theme folder can be wiped on a rebuild. This
plugin touches the theme only through one action hook (`wb_lead_captured`, fired from
`wb_handle_lead()` in `axioralabs_wp/inc-contact.php`) — nothing else couples the two. Deactivating
this plugin has zero effect on the live contact form; it simply stops being captured anywhere but
the sales@ inbox, exactly as before this plugin existed.

---

## 1. Install

1. **WP Admin → Plugins → Add New → Upload Plugin** → `axiora-leads.zip` → **Install** → **Activate**.
2. **Settings → Permalinks → Save Changes** (once, so the `/client-dashboard/` URLs resolve).

Activation does the rest automatically: creates the two database tables and the
**Client Dashboard Admin** role.

Before activating, check **Pages** for an existing page at the slug `client-dashboard` — if one
already exists, the plugin's rewrite rule and that page's own URL would collide.

## 3. Creating an admin login

The portal has its own sign-in screen, but it authenticates against WordPress accounts — so
password hashing, sessions and password resets are all handled by WordPress rather than by
hand-rolled code.

1. **Users → Add New**
2. Set **Role → Client Dashboard Admin**
3. Give them the portal URL. That account can sign in at `/client-dashboard/` and **cannot** reach
   the WordPress dashboard for anything else.

Existing administrators and editors already have access.

---

## 4. What the admin can do

**Dashboard** — total leads, last 7 days with the week-on-week change, how many are awaiting
contact, how many are in progress, how many completed; a 14-day submissions chart; the pipeline
broken down by status; the latest eight leads; and the top automation needs (which "biggest
repetitive process" answer is most common).

**All Leads** — search across name, email, phone, company and reference number; filter by status,
process and date range; sort any column; select several rows and move them to a new status in one
go; page through; export the current view to CSV.

**One lead** — everything submitted, internal notes, and the full activity trail of who changed
what and when.

**Status** — pick a stage, optionally attach a note. Every change is written to the timeline.

### The pipeline

`New` → `Contacted` → `Meeting Scheduled` → `Completed`. To rename or add stages, filter
`axiora_leads_statuses` in a small mu-plugin — nothing else needs changing, the dashboard, filters
and sidebar all read from that one list.

## 5. Security notes

- Every query is prepared; `ORDER BY` is whitelisted.
- Lead capture inherits the contact form's own honeypot, nonce and per-IP rate limit — this plugin
  adds no new public-facing surface of its own.
- All portal writes are nonce-checked and capability-checked.
- The portal is `noindex, nofollow` and drops the WordPress admin bar; unauthenticated visitors see
  a branded login, never the data.
- Deleting the plugin removes its option and role but **deliberately leaves the leads table
  alone** — see `uninstall.php`.

---

## 6. Rebuilding the zip

```bash
node build/build_plugin_zip.js axiora-leads   # from the repo root → axiora-leads.zip
```

Uses the same WordPress-safe ZIP writer as the theme (`build_zip.js`); don't use Windows
"Compress to zip" / PowerShell `Compress-Archive` — it produces backslash paths that break
extraction on Hostinger.
